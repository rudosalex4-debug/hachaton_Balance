# Форматы данных

Одна заявка занимает один файл в каждом срезе. Расширение определяет формат ответа СПР. В одной паре можно совместить JSON с XML или CSV. После чтения приложение сравнивает поля по общим правилам нормализации.

## Проверить на готовом примере

1. В разделе датасетов загрузите папку [tests/fixtures/formats](../tests/fixtures/formats) целиком. В ней две заявки и четыре файла ответов.
2. Создайте конфигурацию для этого набора, оставьте стандартные процедуры и запустите обработку.
3. В результатах сравнения отфильтруйте заявку `0007` и путь `risk.score`. В JSON среза BEFORE значение равно `42`, а в XML среза AFTER оно равно `43`. Оба значения имеют тип `NUMBER`, тип изменения — `VALUE_CHANGED`.
4. Для заявки `0008` CSV и JSON дают одинаковые значения. Для всех её полей `DIFF_FLAG = 0`, включая `0`, `false`, `null` и строку `A, "B"`.
5. В завершённом прогоне раскройте «Выгрузить таблицу целиком», выберите сравнения и формат файла. Выгрузка охватывает обе заявки независимо от текущей страницы и фильтров просмотра.

## Подготовить набор

В корне разместите `manifest.json` и каталоги `RESULTS/BEFORE_MASTER` и `RESULTS/AFTER_BETA`. В `manifest.applications` укажите количество пар. Имя файла без расширения должно совпадать со строкой `appData.application_id` после преобразования. Чтобы сохранить ведущие нули, передавайте `"0007"` как строку. Для каждой заявки в каждом срезе должен быть ровно один ответ.

Сохраняйте файлы в UTF-8. UTF-8 BOM допускается. Профиль одного формата действует для обоих срезов и задаётся в `manifest.input_profiles`. Для JSON достаточно манифеста `{"applications": 2}`. При изменении профиля уже зарегистрированного набора зарегистрируйте обновлённую папку заново.

При загрузке папки через браузер или `POST /api/v1/datasets/upload` суммарный размер содержимого файлов ограничен 48 MiB, размер HTTP-запроса — 64 MiB. Для более крупного набора поместите его в каталог данных и зарегистрируйте через `POST /api/v1/datasets` с телом `{"name":"Мой набор","path":"/data/my-run"}`. Предельный размер одного ответа до и после преобразования — 8 MiB. Для всего набора сервер проверяет предел 512 MiB отдельно для исходных и преобразованных ответов.

## XML

Профиль из примера переименовывает `id` в `application_id`, читает числа и логические значения и превращает элементы `trial` в массив продуктов.

```json
{
  "applications": 2,
  "input_profiles": {
    "xml": {
      "root": "response",
      "rename": {"/appData/id": "application_id"},
      "types": {"/risk/score": "number", "/risk/verified": "boolean"},
      "arrays": {"/decisionResult/product_trials": "trial"}
    }
  }
}
```

Корневой тег служит обёрткой. Дочерние элементы образуют поля объекта, текст листа по умолчанию остаётся строкой. Адреса полей записывают в формате JSON Pointer, например `/risk/score`. В `rename` ключ указывает исходное имя внутри уже преобразованного родителя. В `types` и `arrays` указывают итоговые имена полей.

- `arrays` задаёт путь к обёртке и имя дочернего элемента. Пустая обёртка даёт `[]`, единственный элемент остаётся в массиве. Типы полей объектов внутри массива указывают без индексов. Для массива скалярных чисел `<scores><s>0.7</s></scores>` используйте `"arrays":{"/scores":"s"}` и `"item_types":{"/scores":"number"}`.
- Атрибут `id` доступен как `@id`. В элементе `<cost unit="RUB">42</cost>` доступны поля `@unit` и `#text`. Для числового значения задайте `"types":{"/cost/#text":"number"}`.
- `number` принимает JSON-число с точной десятичной записью, `boolean` — `true` или `false`. Пустой элемент по умолчанию даёт пустую строку. `xsi:nil="true"` из пространства имён `http://www.w3.org/2001/XMLSchema-instance` даёт JSON `null`. Явные типы `object` и `null` позволяют задать смысл пустого элемента.
- Для документов с одним пространством имён элементов укажите его URI в `namespace`. Парсер отклоняет объявления DTD и пользовательских сущностей, дубли полей, а также содержательный текст вперемешку с дочерними элементами. Предопределённые записи наподобие `&amp;` поддерживаются.

Когда XML содержит массив, настройте также правило сопоставления массива в конфигурации анализа. Например, у `decisionResult.product_trials` стандартное правило уже использует `product_id`.

## CSV

По умолчанию CSV содержит заголовки `pointer,type,value`. Каждая строка описывает одно значение документа заявки. Пример сохраняет ведущие нули ID и различает ноль, пустую строку и `null`.

```csv
pointer,type,value
/appData/application_id,string,0008
/risk/score,number,0
/risk/verified,boolean,false
/risk/comment,null,
/risk/label,string,"A, ""B"""
/risk/empty,string,
```

В JSON Pointer используйте `~1` вместо `/` внутри имени и `~0` вместо `~`. Пути `/scores/0` и `/scores/1` создают массив. Индексы образуют непрерывную последовательность от нуля, строки могут идти в любом порядке. Запись `/scores,array,` задаёт пустой массив. Запись `/codes,object,` позволяет использовать числовые имена полей внутри объекта. Повторное объявление одного пути и дочерние поля под скалярным значением отклоняются.

Параметр `delimiter` принимает запятую, точку с запятой или табуляцию (`"\t"` в JSON). В `columns` можно переименовать три заголовка, например `{"pointer":"Путь","type":"Тип","value":"Значение"}`. Для значений с разделителем, кавычками или переносом строки используйте двойные кавычки, а внутреннюю кавычку удваивайте.

Для привычной таблицы с заголовком и одной строкой данных на файл задайте `layout: "record"`. Сопоставьте каждую колонку с полем заявки. Следующий профиль подходит для файла `0008.csv` с заголовком `id,score` и строкой `0008,0`.

```json
{
  "applications": 1,
  "input_profiles": {
    "csv": {
      "layout": "record",
      "fields": {
        "id": {"pointer": "/appData/application_id", "type": "string"},
        "score": {"pointer": "/risk/score", "type": "number"}
      }
    }
  }
}
```

## Получить результаты через API

После входа выполните `GET /api/v1/runs/{id}/export?artifact=comparisons&format=json`. Доступ имеет владелец завершённого прогона. Параметр `artifact` принимает `normalized` (оба среза), `comparisons` (сопоставленные значения), `facts` (агрегированные группы) или `checks` (результаты проверок). Имя файла имеет вид `run-{id}-{artifact}.{format}`.

| Формат | Содержимое файла |
|---|---|
| `json` | Массив объектов с полями витрины. Списки заявок `APP_IDS` остаются массивами. |
| `xml` | Корень `<rows>` содержит элементы `<row>`. Поля имеют вид `<field name="CNT" type="number">2</field>`. Массив содержит элементы `<item>`, объект — вложенные `<field>`. Для строки с недопустимым в XML символом атрибут `encoding="json"` указывает на JSON-представление строки. Для таких имён полей применяется `name-json`. |
| `csv` | Таблица с запятой, заголовком и окончаниями строк CRLF. Колонки охватывают поля всех строк. Массивы и объекты записаны как компактный JSON. Отсутствующее поле обозначается `\M`, JSON `null` — `\N`. Пустая строка даёт пустую ячейку. У строки с начальным `\` этот символ удваивается. Максимум 4 096 колонок. |

Самостоятельный HTML-отчёт доступен по `GET /api/v1/runs/{id}/report.html`. Он содержит сводку, все результаты проверок и ссылку в интерактивную сводную. Скачанный отчёт можно открыть без сервера.

## Подключить ещё один входной формат

Реализуйте функцию чтения одного ответа в [backend/src/input_formats.cpp](../backend/src/input_formats.cpp) и зарегистрируйте её расширение в таблице `adapters`. Она должна вернуть JSON-объект заявки с точными числовыми значениями или сообщить об ошибке преобразования. Сервер использует этот реестр при регистрации и загрузке файлов. Для выбора файлов в браузере добавьте расширение в [DatasetUpload.tsx](../frontend/src/DatasetUpload.tsx). Проверьте эквивалентность результата исходному JSON на одном и том же наборе правил в [тестах адаптеров](../backend/tests/input_formats_test.cpp).
