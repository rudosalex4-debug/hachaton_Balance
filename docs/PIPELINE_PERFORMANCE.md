# Обработка срезов BEFORE и AFTER

Нативные нормализаторы выдают канонические типы и значения. В каждой заявке строки упорядочены по пути и ключу элемента массива. Нативное сравнение использует это свойство и сразу строит строки результата слиянием двух диапазонов. Для N и M строк требуется O(N + M) шагов слияния, без учёта длины сравниваемых строк и стоимости вывода. При неизменном формате отчёта требуется вывести и совпавшие атрибуты. Пользовательский ввод на границе процедур проходит валидацию. Общий компаратор проверяет порядок и при необходимости сортирует соответствующую сторону.

Нативные этапы нормализации и сравнения работают с одной парой в памяти. Сегменты используют готовое сравнение для флагов изменений. Нормализованные строки и строки сравнения записываются в одной транзакции на пакет. Запись пакета происходит после завершения заявки при достижении порога 8192 строк или 100 заявок. Крупная заявка может превышать порог. Для пользовательских процедур сохраняется разбивка по 100 заявок.

Нативная агрегация без Python-проверок читает сравнения из PostgreSQL курсором по 512 строк. Группы и связи с заявками накапливаются до завершения агрегации, затем упорядочиваются для выдачи. Если проверке или агрегатору Python нужен полный массив, сервер читает его один раз и передаёт процедурам. При старте обработки исходные документы всё ещё занимают память до потребления своих пакетов.

Числовые границы нормализатор разбирает при первом использовании правила и находит интервал двоичным поиском. Соответствие пути правилу запоминается на время обработки документа. При записи через COPY сериализатор использует один буфер для последовательных строк.

Сборка Docker использует локальный кеш ccache для единиц трансляции. Первая установка зависимостей и первая полная компиляция по-прежнему требуют времени. Подробности приведены в [BUILD_PERF.md](BUILD_PERF.md). Исходные планы запросов и назначение индексов описаны в [STORAGE_PROFILE.md](STORAGE_PROFILE.md).

Финальные изменения оценены по коду. Сравнительный прогон итогового варианта не выполнялся. Для диагностики отдельного запуска можно включить LENS_PROFILE=1 в окружении Docker Compose и посмотреть summary.profile в результате запуска. По умолчанию профиль выключен.
