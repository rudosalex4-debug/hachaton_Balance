# Время сборки backend

Docker собирает Release на Ubuntu 24.04 с g++, Ninja и двумя параллельными заданиями. В runtime попадают исполняемый файл, миграции, исходники встроенных процедур, динамические библиотеки и curl для healthcheck. Слой с runtime-пакетами также служит основой для компилятора. Самостоятельный `core_benchmark` остаётся доступным при обычной сборке CMake. Docker отключает его через `BUILD_BENCHMARK=OFF`. Все тесты CTest собираются и запускаются перед копированием сервера.

## Повторная сборка

BuildKit монтирует исходники и фикстуры на время компиляции. Изменение исходника, заголовка, CMakeLists или фикстуры инвалидирует шаг сборки. Внутри этого шага CMake всегда создаёт новый каталог. В локальном кеше BuildKit остаются результаты ccache для отдельных единиц трансляции. ccache использует обработанный препроцессором текст с учётом заголовков, параметры компиляции и содержимое g++. В ключ также входят контрольные суммы cc1plus и ассемблера. Это позволяет переиспользовать результаты для прежнего содержимого файлов после переключения ветки или восстановления даты изменения. При выполнении шага компиляции с пустым ccache компилятор заново обрабатывает все единицы трансляции. [Docker BuildKit](https://docs.docker.com/build/cache/optimize/) и [руководство ccache](https://ccache.dev/manual/4.9.1.html).

```bash
docker build --progress=plain -f backend/Dockerfile -t decision-lens-backend:local .
```

Для другого числа параллельных заданий передайте `--build-arg BUILD_JOBS=4`. Когда BuildKit выполняет шаг компиляции, в логе видны результат CTest и счётчики ccache. Для целиком повторно использованного слоя Docker выводит `CACHED`. Кеш локален для Docker builder и архитектуры. Для первой сборки без предзагруженных слоёв нужен доступ к образу Ubuntu и его пакетным репозиториям. Скрипт `scripts/build-wsl.sh` собирает проект с уже установленными зависимостями локально без Docker и сетевых загрузок.
